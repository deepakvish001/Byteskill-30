## Objects: The Foundation {#objects-foundation}
In JavaScript, objects are fundamental. Almost everything is an object, or can behave like one. An object is a collection of key-value pairs, where keys are strings (or Symbols) and values can be any data type, including other objects or functions (methods).

## Creating Objects {#creating-objects}
There are several ways to create objects:

1.  **Object Literals:** The simplest way.
    \`\`\`javascript
    const person = {
      name: "Byteskill",
      greet: function() {
        console.log(\`Hello, I'm ${this.name}\`);
      }
    };
    person.greet(); // Hello, I'm Byteskill
    \`\`\`

2.  **`Object.create()`:** Creates a new object with a specified prototype object and properties.
    \`\`\`javascript
    const animal = {
      makeSound: function() {
        console.log("Generic sound");
      }
    };
    const dog = Object.create(animal);
    dog.breed = "Labrador";
    // dog.makeSound(); // Generic sound (inherited)
    \`\`\`

## Constructor Functions & `new` {#constructor-functions}
Constructor functions are regular functions used with the `new` keyword to create objects. By convention, their names start with a capital letter.

\`\`\`javascript
function Person(name, age) {
  this.name = name;
  this.age = age;
  // Methods are typically added to the prototype (see below)
}

const person1 = new Person("Alice", 30);
const person2 = new Person("Bob", 25);
console.log(person1.name); // Alice
\`\`\`
When `new Person(...)` is called:
1.  A new empty object is created.
2.  This new object is set as the `this` context for the constructor function.
3.  The constructor function executes, adding properties to `this`.
4.  The new object is implicitly returned (unless the constructor explicitly returns a non-primitive value).

## The `this` Keyword {#this-keyword}
The value of `this` in JavaScript depends on how a function is called (its invocation context):
*   **Global context:** `this` refers to the global object (`window` in browsers, `global` in Node.js).
*   **Function context (simple call):** `this` also refers to the global object (or `undefined` in strict mode).
*   **Method context (`object.method()`):** `this` refers to the object the method was called on.
*   **Constructor context (`new Func()`):** `this` refers to the newly created instance.
*   **Arrow functions:** `this` is lexically bound; it inherits `this` from the surrounding (enclosing) scope.
*   **Explicit binding (`.call()`, `.apply()`, `.bind()`):** You can explicitly set the value of `this`.

Understanding `this` is crucial for object-oriented programming in JavaScript.

## Prototypes Explained {#prototypes-explained}
Every JavaScript object has a prototype. A prototype is also an object. When you try to access a property on an object, if the property is not found on the object itself, JavaScript looks for it on the object's prototype, then on the prototype's prototype, and so on, up the **prototype chain** until it's found or the chain ends (with `null`).

Objects inherit properties and methods from their prototype.

\`\`\`javascript
function Dog(name) {
  this.name = name;
}

// Add a method to Dog's prototype
Dog.prototype.bark = function() {
  console.log(\`Woof! My name is ${this.name}\`);
};

const myDog = new Dog("Buddy");
myDog.bark(); // Woof! My name is Buddy (bark is found on Dog.prototype)
console.log(myDog.hasOwnProperty('bark')); // false
console.log(Dog.prototype.hasOwnProperty('bark')); // true
\`\`\`
This is more memory efficient than defining methods directly in the constructor, as all instances share the same method from the prototype.

## Prototypal Inheritance {#prototypal-inheritance}
Prototypal inheritance is how JavaScript achieves code reuse and creates relationships between objects. You can set an object's prototype using `Object.create()` or by setting the `prototype` property of a constructor function.

\`\`\`javascript
function Animal(legs) {
  this.legs = legs;
}
Animal.prototype.walk = function() {
  console.log(\`Walking on ${this.legs} legs.\`);
};

function Bird(name) {
  Animal.call(this, 2); // Call Animal constructor to set legs
  this.name = name;
}

// Set up inheritance: Bird's prototype should be an Animal instance
Bird.prototype = Object.create(Animal.prototype);
Bird.prototype.constructor = Bird; // Reset constructor property

Bird.prototype.fly = function() {
  console.log(\`${this.name} is flying!\`);
};

const sparrow = new Bird("Sparrow");
sparrow.walk(); // Walking on 2 legs. (Inherited)
sparrow.fly();  // Sparrow is flying!
\`\`\`

## ES6 Classes (Syntactic Sugar) {#es6-classes}
ES6 introduced the `class` syntax, which provides a cleaner, more familiar way to create objects and implement inheritance. However, it's important to remember that ES6 classes are primarily syntactic sugar over JavaScript's existing prototypal inheritance.

\`\`\`javascript
class AnimalES6 {
  constructor(legs) {
    this.legs = legs;
  }
  walk() {
    console.log(\`Walking on ${this.legs} legs (ES6).\`);
  }
}

class BirdES6 extends AnimalES6 {
  constructor(name) {
    super(2); // Calls AnimalES6 constructor
    this.name = name;
  }
  fly() {
    console.log(\`${this.name} is flying (ES6)!\`);
  }
}

const eagle = new BirdES6("Eagle");
eagle.walk(); // Walking on 2 legs (ES6).
eagle.fly();  // Eagle is flying (ES6)!
\`\`\`

<Callout iconName="Info" variant="info" title="Under the Hood">
Even with `class` syntax, JavaScript's inheritance model remains prototypal. Understanding prototypes helps you grasp what's happening behind the scenes.
</Callout>

## Conclusion {#conclusion}
JavaScript's object model and prototypal inheritance are powerful, flexible, and sometimes tricky. Mastering these concepts, including how `this` works and how to leverage prototypes (or the `class` syntax effectively), is key to writing robust and scalable JavaScript applications.
